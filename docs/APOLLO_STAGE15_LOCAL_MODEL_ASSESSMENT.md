# Stage 15 local model assessment

Only the existing pinned model was executed. No replacement weights were downloaded, trained, converted or benchmarked. ONNX Runtime is an execution engine; changing its format does not add clinical labels, medication relations or temporal reasoning.

The local `run_manifest.json` identifies a BiLSTM configuration with 128-dimensional embeddings/hidden state, a 20,000-token vocabulary and nine label slots. Its recorded class counts contain only O, CONDITION and MEDICATION BIO labels. DOSAGE/ANATOMICAL_SITE output slots therefore do not establish trained attribute recognition. The deployed INT8 graph is 3,246,078 bytes. Production verifies the exact pinned graph/tokenizer hashes, input/output types and label dimensions. The training manifest's tokenizer hash differs from the deployed tokenizer manifest/hash: training provenance is not fully reconciled, and exact reference-tokenizer parity is not claimed.

The [joint entity/assertion research](https://arxiv.org/abs/1812.05270) illustrates task-specific assertion training. A licensed, reproducible task checkpoint suitable for this deployment was not established from that paper, so it is research evidence rather than an implemented model improvement.

All replacement-model peak memory, quantized accuracy, CPU inference latency, relation accuracy and deployment complexity remain NOT MEASURED locally. None may be called superior based on size, release date or a publisher's own benchmark. The current nine-label integrity-pinned adapter cannot safely load a 25-label model: a new explicitly versioned adapter and independent evaluation would be required.

The implemented choice is the existing small CPU ONNX model plus dedicated C# clinical components. Measured results support this engineering iteration only. Independent annotation and mapping adjudication are still needed before deciding whether a specialized model provides a measurable clinical benefit on the actual 16 GB, integrated-graphics development machine.
